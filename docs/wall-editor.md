# Dedicated wall editor and UVTT export

## Workflow

From a map's fog editor, choose Walls → Open wall editor. Opening the screen
neither shows the map to players nor changes fog. It edits that map's current
walls, not an original uploaded source. Maps without walls can start from scratch.

Select Add wall and a type, then click its two endpoints. The nearest existing
endpoint within 10 screen pixels is used when snapping is enabled. Escape cancels
a pending start. Choose Remove wall or Change wall type, then click within
10 screen pixels of the target. Where lines overlap, the closest line wins;
equally close lines prefer the most recently listed segment. Zoom in to disambiguate.
Drag pans, wheel zooms, F fits. Undo/Redo covers up to 1000 draft operations;
Ctrl/Cmd+Z undoes, Ctrl/Cmd+Shift+Z redoes. Tools wait for metadata and artwork.

Save wall set commits the draft immediately with no Apply confirmation. In one
SQLite transaction it saves a wall-only UVTT source, replaces this map's segments,
bakes alignment into image pixels and resets calibration to identity. The original
source is never overwritten; identical generated bytes reuse a campaign source.
Changed versions have the same map-N-walls.uvtt filename but distinct source IDs.
The scene name is retained in the extension. Other maps remain unchanged.

Download UVTT exports the current draft, including unsaved edits, without saving
or applying. A downloaded draft can be uploaded through Saved wall sources later.
The image checkbox affects downloads only; stored reusable sources remain wall-only.
The canonical map image can be embedded as base64 for self-contained interchange.
An export without image is intended for wall reuse with a separately supplied map;
not every third-party VTT accepts wall-only files.

Pixels per grid defaults to 70. Choosing another value changes serialization
units, not the overlay's position or size. Export coordinates are calibrated
image pixels divided by pixels per grid; map_size uses the same units and
map_origin is zero. Reimport with auto-align restores the original size.

## Boundaries and safety

All six kinds are editable, even if hidden or disabled in the fog editor.
New/retyped ethereal segments have blocks=false; other kinds have blocks=true.
Existing imported blocking flags are retained for untouched segments. Show/Enabled
and Doors split areas remain map-level settings and are not baked into a wall set.
Thus a saved set can be reused on a map with different boundary settings.

Save retains fog operations and snapshots and notifies viewers through the
existing refresh path. It does not activate or blank the map. Blank players before
boundary edits during play: replayed reveals can expand when rooms merge. After
saving, inspect the exact player preview and reset fog if appropriate.

Nothing is autosaved. The page warns before leaving a modified draft. Reload
asks before discarding edits. Saving resets local undo/redo history. Version and
map-incarnation checks reject stale saves with 409, covering alignment, artwork,
wall edits and deletion/recreation. Download without image can rescue an old draft;
then reload saved walls and reconcile. Including artwork requires the original
artwork version/dimensions to match, otherwise 409 avoids attaching the wrong image.

The editor performs no background poll that could replace a draft. A separate
tab's saved-source menu may need Refresh sources. Server-side geometry, count and
export-size limits return explicit errors. Very large drafts can be slow to render;
there is no spatial index or grid-drawing tool in this patch. Request bodies are
parsed by FastAPI before generated-export size checks; existing deployment request
limits should still be used. External URLs and filesystem paths are never fetched
from UVTT data. Existing authorized canonical image storage is used for embedding.

## UVTT interchange and exact wall types

Core output uses UVTT format 0.2, resolution, line_of_sight,
objects_line_of_sight, portals, lights and environment fields. This is a wall
editor, not a scene-preservation editor: imported lights, arbitrary source metadata,
portal open states and source background settings are not retained or synthesized.
Normal doors are exported closed. No third-party VTT compatibility is claimed as tested.

| Looking Glass kind | Standard fallback | Exact reimport here |
|---|---|---|
| wall | line_of_sight | wall |
| door | closed portal | door |
| secret | line_of_sight, so it is not exposed as an obvious door | secret |
| window | line_of_sight | window |
| invisible | objects_line_of_sight; third-party treatment varies | invisible |
| ethereal or nonblocking segment | omitted from standard blockers | retained by extension |

The looking_glass extension has version=1, name, segments in grid units and a
SHA-256 checksum of the core geometry/resolution fields. Each segment stores
x1,y1,x2,y2,kind,blocks, preserving all kinds and passive segments. This is an
application extension, not a claim that core UVTT standardizes all six types.
An unaware importer uses only fallback fields and may lose these distinctions.

The checksum detects another program changing standard geometry while leaving
stale extension coordinates. This case is rejected rather than silently importing
outdated walls. Remove the entire looking_glass field to import standard geometry
only, accepting type loss. An ordinary UVTT file with no extension follows the
existing parser unchanged. Unsupported extension versions are rejected explicitly.
Empty edited sets are valid and can be saved/reimported.

## Modules and compatibility

- services/uvtt_export.py: validation, standard geometry, lossless extension, JSON.
- services/foundry_import.py: recognizes the extension before ordinary UVTT parsing.
- web/admin/wall_editor.py: admin-only HTML, full-precision state, transactional save,
  draft download and saved-set download, using existing permission/CSRF dependencies.
- static/js/admin_wall_editor.js: draft editing using the existing PanZoom component.
- web_html/admin/wall_editor.html and static/css/wall_editor.css: separate UI.
- web/app_factory.py: mounts the router on the admin app only.

No schema migration is introduced. This patch targets commit
ba2f4bf699d3e72e6f6988a718f9a93cbca04343 and assumes its existing migrations are healthy.
It does not repair earlier migration collisions. See ../Patch/wall-editor-uvtt.md
for installation, rollback and exact verification scope.
