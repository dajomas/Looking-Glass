# I3: Playwright end-to-end suite and results publishing (2026-11-23)

Requested 2026-11-23: a Playwright end-to-end suite for Chromium and Firefox, a
`tools/` script that runs it, stores results in `e2e-results/<timestamp>/`,
keeps only the latest set and commits and pushes it with `[skip ci]`. The
user supplied the Scrying Glass `tools/run_e2e.sh` as the starting point.

## Delivered

- `e2e/`: `requirements.txt` (application requirements, pytest, Playwright,
  pytest-playwright, pytest-html), `pytest.ini` (both browsers, screenshots
  only on failure, traces retained on failure), `conftest.py`, `support.py`,
  `test_journeys.py`, `README.md`.
- Server: one `python/main.py --config <tmp> serve` subprocess per session on
  free loopback ports outside the browsers' unsafe-port list, a throwaway data
  directory, `LG_*` environment variables removed and the superadmin created
  from `LG_SUPERADMIN_PASSWORD`; PNG fog, no feathering and work resolution 400
  make pixel checks exact. Startup waits for both `/healthz` endpoints; teardown
  sends SIGINT, then kills after 15 s. The whole server log is saved with the
  results.
- Journeys (each in both browsers, 7 tests, 14 cases), all through the real UI;
  test data use unique names so tests share the server safely:
  wrong password rejected; campaign creation, map import with Foundry walls,
  player creation, Show, the player's forced change from a direct `/c/<id>`
  link landing on the live map (I1), and a reveal reaching the player; hide and
  undo; a wall-editor endpoint drag (I2) moving the room boundary seen by the
  player; voluntary password change staying on `/account`; the admin portal
  refusing a player, logout and the session ending; deactivation from the
  Users page sending the live player to the login page.
- Failure artifacts in `failures/<test>/`: pytest-playwright screenshots and
  `trace.zip`, plus `console.txt` (console and uncaught errors for every page)
  and `server-log.txt` (server output during the test). Uncaught page errors
  fail the test.
- `tools/run_e2e.sh`, adapted from Scrying Glass: default branch
  `features/claude`; Python 3.14 venv (`E2E_PYTHON`, `.venv-e2e`), refusing an
  older one; `E2E_HEADED=1`; dnf package check and browser preflight kept; the
  summary also lists uncommitted changes to tracked files; `server.log` added
  to the files list; the generated commit has no co-author trailer.
- `.gitignore`: `.venv-e2e/` and `e2e-results/_local/` ignored; `*.zip` is
  re-allowed under `e2e-results/` so traces are committed.
- Documentation: `docs/testing.md` "End-to-end suite", `e2e/README.md`,
  release notes; TODO item I3.

## Validation in this session

This workspace has no Playwright browsers, no FastAPI and no network for
installs, so the suite itself has not run here. Checked: `bash -n`, Python
parsing of the suite, the summary generator against a JUnit sample with
pytest-playwright test ids (totals and per-browser counts), and an end-to-end
run of the script's git handling with a stand-in interpreter in a temporary
repository: the old results folder was removed, the new set committed, and a
competing commit pushed mid-run caused one refused push, a rebase and a
successful push. The selectors were taken from the current templates and
mirror the in-process live tests. The first real run (`tools/run_e2e.sh`) is
the evidence still needed; CI does not run the suite.
