# Second bug hunt: bugs 16–29

Date: 2026-10-31. Repository: `dajomas/Looking-Glass`.
Target: `features/perplexity`.
Audited commit: `766780262bf44922bbd7c9fa2b3081e7e28e214f`.

## Scope and evidence limits

All findings below are open. Source paths are repository-relative and refer to
the audited commit; function names identify the relevant locations. The review
covered selected authentication, configuration, campaign/image, fog, note,
viewer and editor paths and supporting repositories/schema triggers. It was
not an exhaustive inspection of every repository file. Application tests, a
normal checkout, HTTP requests, browser sessions, server concurrency tests and
CI were not executed. Proposed reproduction procedures and regression cases
below are work to perform, not claims that they passed or failed here.

Three small extracted checks were actually executed in the assistant sandbox:

1. The `CalibrationIn` field declarations copied from `web/admin/api.py`, under
   sandbox Pydantic 2.11.4, accepted `offset_x="Infinity"`; a temporary in-memory
   SQLite REAL NOT NULL column retained the resulting positive infinity.
2. Node evaluated the `_safe_next` predicate against the two-character slash /
   backslash prefix followed by `example.invalid`. It accepted the value; the
   WHATWG URL constructor resolved it against `https://looking-glass.invalid`
   to `https://example.invalid/`. This was not an HTTP/browser navigation test.
3. Node evaluated the polling inequality with current fog version 10 and late
   response version 8. The assignment replaced 10 with 8. This was not execution
   of the complete editor script or a mocked-network application regression.

These checks support bugs 16, 20 and 25 respectively. They do not establish
application-level persistence, exploitability or integration acceptance.
Remaining findings are source-grounded static findings awaiting reproduction.

Schema review ruled out two apparent bugs: `hide_all` triggers clear runtime
doors/passages, and double-reveal table triggers increment `fog_version`.
Neither is included. Bugs 1–15 retain their existing status. In particular,
17/18 concern original-image replacement, explicitly outside bug 15's delivered
retirement scope; 16 concerns the direct calibration API, not import validation.

## 16. Manual calibration bypasses finite-number validation

- [ ] Open; isolated model/SQLite behavior reproduced, application reproduction pending.
- Evidence: `python/looking_glass/web/admin/api.py`, `CalibrationIn` and
  `calibration`; `repositories/maps.py`, `set_calibration`. Offsets are unrestricted
  floats; unlike import validation there is no finite/transformed-coordinate
  validation before the SQL update. Scale bounds alone do not prevent overflow
  when multiplied by very large finite offsets.
- Impact: accepted input can reach invalid geometry, non-JSON-safe payloads or
  rendering failures. Persistence depends on where response construction fails;
  do not claim every invalid request commits.
- Reproduce: with an authorized CSRF-protected client, submit string `Infinity`
  as an offset on a disposable wall-free map; separately exercise very large
  finite offsets with walls. Inspect response, stored calibration and subsequent
  admin/viewer rendering, including rollback paths.
- Fix: reject non-finite fields and non-finite transformed endpoints before any
  write, reusing the import numeric policy without changing ordinary negatives.
- Regression: HTTP/real DB rejection leaves versions, geometry and fog unchanged;
  finite ordinary calibration still succeeds. Related: bug 11, separate API path.

## 17. Original-image replacement deletes files still in use

- [ ] Open; static lifecycle finding; concurrency reproduction pending.
- Evidence: `web/admin/campaigns.py`, `replace_image`, commits the new image then
  calls `images.delete_map_image` on the old original. `web/admin/api.py`,
  `map_image`, returns a deferred `FileResponse`; viewer rendering also captures
  an old `MapSpec` before its worker opens the original. Neither old reader is
  protected by this unlink. Bug 15 retires alternate replacements, not originals.
- Impact: replacement can break already-authorized in-flight image responses or
  composite renders with missing-file failures. Fog-engine cache locks cannot
  prevent an unlink performed outside those locks.
- Reproduce: pause an original FileResponse or cold viewer render after path
  selection and before file opening; replace the original and resume the reader.
- Fix: transactionally retire the superseded original and defer collection to
  coordinated offline maintenance, using the existing retirement foundation.
- Regression: both old reader and subsequent new reader complete successfully;
  old path is retained until explicit collection and rollback does not retire it.

## 18. Old-image unlink failure interrupts post-commit notification

- [ ] Open; static failure-path finding; fault injection pending.
- Evidence: `web/admin/campaigns.py`, `replace_image`, performs old-file deletion
  after the new database state commits but before `ctx.fog.invalidate` and
  `notify.map_changed`. `images.delete_map_image` does not suppress unlink errors.
- Impact: permission/read-only/storage errors can report a failed replacement
  after it committed, skip the immediate viewer notification and encourage a
  duplicate retry. Polling may eventually recover; this is not permanent viewer
  corruption or loss of the newly committed image.
- Reproduce: arrange successful new-image storage/commit, then inject OSError on
  deletion of the old path; observe committed row, HTTP failure and absent notify.
- Fix: preferably remove online unlink through bug 17's retirement design. Any
  remaining cleanup must not prevent post-commit invalidation/notification.
- Regression: cleanup failure preserves the committed result and update delivery;
  document/log deferred cleanup without claiming rollback after commit.

## 19. Superadmin self-reset leaves other sessions valid

- [ ] Open; static session-revocation finding; HTTP/socket reproduction pending.
- Evidence: `web/admin/users.py`, `reset_password`, deletes sessions and calls
  `kick_user` only if `user_id != user["id"]`. Self-reset changes the password but
  skips revocation of every other session for that same superadmin. In contrast,
  `web/auth_routes.py`, `account_submit`, deletes other sessions on password change.
- Impact: an old session in another browser or the viewer portal remains usable
  after the superadmin resets their own password, unless another gate intervenes.
- Reproduce: create two admin sessions and a viewer session for one superadmin;
  self-reset via `/users/{id}/password` with `must_change=false`; reuse old tokens.
- Fix: revoke all other sessions while optionally preserving the requesting token;
  disconnect only revoked sockets and retain normal self-service behavior.
- Regression: retained current session works, all other tokens fail and their
  sockets close/recheck as designed; other-user password reset still revokes all.

## 20. Login next accepts a cross-origin backslash redirect

- [ ] Open; isolated predicate/WHATWG URL behavior reproduced; HTTP/browser pending.
- Evidence: `web/auth_routes.py`, `_safe_next`, accepts any initial slash except
  literal double slash and `/login`. A slash followed by a backslash passes.
  Special-scheme URL parsing treats the backslash as a separator.
- Impact: a crafted login URL/form can redirect the user to an external site
  following login or an already-authenticated login-page visit. This does not by
  itself disclose the HttpOnly session cookie or establish account compromise.
- Reproduce: pass `/` followed by `\` then `example.invalid` as `next`; check the
  actual Location response and browser destination on both login paths.
- Fix: validate a local path after consistent normalization; reject backslashes,
  control characters and network-path references. Preserve valid local query strings.
- Regression: slash/backslash and encoded/normalization variants stay local;
  ordinary campaign/account return paths remain supported.

## 21. Login lacks cross-site submission protection

- [ ] Open; static login-CSRF finding; browser exploitability validation pending.
- Evidence: `web/auth_routes.py`, `login_submit`, has no pre-authentication CSRF
  check and no Origin/Referer validation. `web/app_factory.py`, `SecurityHeaders`,
  adds response headers but no request-origin gate. Existing `verify_csrf`
  requires authentication and is not attached to login.
- Impact: cross-site form submission can attempt to sign a browser into an
  attacker-chosen valid account, confusing account/campaign identity. Browser
  cookie/navigation behavior and deployment origin policy must be tested; lack
  of a login token is not a bypass of CSRF protection on authenticated mutations.
- Reproduce: host a separate-origin form with known valid credentials and submit
  it to a disposable installation; inspect session identity after navigation.
- Fix: implement a pre-login challenge or carefully configured same-origin
  validation compatible with both portals and supported reverse proxies.
- Regression: cross-origin login submission is rejected; normal login, expired
  sessions and both portal listeners still work. Do not log submitted passwords.

## 22. Multipart CSRF token can cause an unhandled type error

- [ ] Open; static malformed-input finding; HTTP reproduction pending.
- Evidence: `web/deps.py`, `verify_csrf`, takes `form.get("csrf_token")` without
  checking its type; `security.py`, `constant_eq`, calls `.encode()` on truthy
  inputs. A multipart file field under that name yields an UploadFile, not text.
- Impact: malformed authenticated input produces an unhandled AttributeError/500
  rather than Forbidden. No CSRF bypass or unauthorized write is established.
- Reproduce: valid session, no CSRF header, multipart file named `csrf_token` on
  a protected form endpoint; ensure route mutation never runs.
- Fix: require a string token before constant-time comparison; normalize invalid
  multipart shapes to the existing CSRF error.
- Regression: missing, empty, file-valued, wrong and valid string tokens plus
  valid header tokens return the intended status without server errors.

## 23. Explicit missing configuration silently falls back to defaults

- [ ] Open; static configuration-selection finding; startup reproduction pending.
- Evidence: `config.py`, `load_settings`, records a path selected by argument or
  `LG_CONFIG`, but only reads it if `cfg_path.exists()`. A nonexistent explicitly
  requested file therefore returns Settings based on defaults/environment.
- Impact: a typo or missing deployment mount can start against unintended default
  storage/listeners/security settings instead of failing startup. Impact depends
  on environment overrides; this is not a claim of automatic data deletion.
- Reproduce: point `--config` and separately `LG_CONFIG` at a nonexistent file;
  inspect chosen database path and listeners using isolated disposable storage.
- Fix: distinguish optional auto-discovery from explicitly requested configuration;
  missing/unreadable explicit files must fail clearly before bootstrap writes.
- Regression: explicit missing file fails without creating a DB/account; absent
  optional default config still uses documented defaults; valid overrides work.

## 24. Malformed configuration structures bypass loader validation

- [ ] Open; static configuration-validation finding; loader/startup tests pending.
- Evidence: `config.py`, `_deep_merge` and `load_settings`, assume a top-level
  mapping and permit scalar/null replacements for known section mappings. A YAML
  list reaches `.items()`; `server: null` or `storage: false` survives merge until
  later indexed access fails. Only scrying-glass options receive explicit validation.
- Impact: malformed configuration causes inconsistent, late low-level failures
  rather than a useful error naming the offending section. No successful malformed
  startup or security bypass is claimed.
- Reproduce: load a YAML list and known sections set to null/scalars in isolated
  files; inspect failure stage and diagnostics before any application writes.
- Fix: validate top-level/known-section shapes and important numeric ranges before
  returning Settings. Preserve supported optional unknown extension keys if needed.
- Regression: shape errors identify the field and fail before directory/bootstrap
  changes; valid partial mappings retain their existing deep-merge behavior.

## 25. Delayed admin polling can roll editor state backwards

- [ ] Open; isolated inequality behavior reproduced; network/browser pending.
- Evidence: `static/js/admin_map_editor.js`, final setInterval, calls `applyState`
  whenever returned fog/wall versions differ; it has no request-generation guard
  and is not coordinated with action responses or `busy`. A pre-action GET can
  finish after a mutation and overwrite newer state. Cache incarnation is also
  absent from the polling comparison.
- Impact: stale calibration/overlays can replace current editor state. Ordinary
  reveal/hide requests do not carry a server-validated version stamp, so acting
  on that stale geometry is not automatically rejected (unlike door gestures).
- Reproduce: delay a poll snapshot, complete a wall/fog mutation, then release the
  old poll. Also test deletion/restore incarnation replacement and overlapping polls.
- Fix: sequence GET/action state installation with incarnation-aware request
  generations; never order random cache tokens lexicographically. Consider server
  stale-context protection for ordinary coordinate actions separately.
- Regression: delayed poll cannot undo a newer action result or install a previous
  incarnation; normal external-DM changes still converge.

## 26. Mask early return does not invalidate an in-flight different mask

- [ ] Open; static ABA response-order finding; controlled decode test pending.
- Evidence: `static/js/admin_map_editor.js`, `loadMask`, checks `key === maskKey`
  and returns before incrementing `maskGeneration`. Sequence: installed mask A;
  request mask B; apply late state A; the A call returns early; B then decodes and
  still matches its generation, installing B while global state is A.
- Impact: wrong fog/arrow overlay is drawn; maskKey/stateKey mismatch may disable
  taps until another refresh. This depends on non-monotonic state arrival, notably
  bug 25; it is not an independent normal monotonic-version failure.
- Reproduce: controlled Image.decode promises for A/B with that exact ordering.
- Fix: invalidate obsolete pending decodes even on the cache-hit path and recheck
  requested identity against current state before installing both images.
- Regression: A→B pending→A cannot install B; superseded failures and successful
  decodes do not change the current overlay. Implement after/with bug 25.

## 27. Notes-only changes do not refresh other editors

- [ ] Open; static synchronization finding; two-editor browser test pending.
- Evidence: `db.py` migration 18 increments `room_notes_version` on note writes;
  `web/admin/api.py`, `_map_payload`, omits that field. The polling comparison in
  `static/js/admin_map_editor.js` and the stamp in `static/js/room_notes.js`,
  `refresh`, track fog/walls but not notes version. Clean visible room content is
  not fetched again merely because another editor saved notes or unassigned them.
- Impact: other DMs can continue reading obsolete names/notes and picker assignment
  state without knowing it changed. Existing server save-context checks still
  protect stale writes; this is not a claim that those checks can be bypassed.
- Reproduce: two open editors, same selected named room; save/clear/unassign in one
  without fog or wall edits; wait beyond the polling interval in the other.
- Fix: expose/track notes revision, reload clean selected-room/library state when
  it changes, and preserve dirty drafts with explicit stale-context feedback.
- Regression: clean panels converge; dirty drafts remain intact and cannot silently
  overwrite changed notes; library assignment availability converges too.

## 28. Out-of-map fog points are clamped into real rooms

- [ ] Open; static coordinate-validation finding; HTTP/pixel test pending.
- Evidence: `web/admin/api.py`, `Point`, permits negative and out-of-image values
  within ±1e7. `_fog_op` uses `describe_click` without a map-bound check;
  `services/fog.py`, `label_at`, clamps coordinates to edge pixels, possibly snapping
  from an edge wall to a nearby room. `_room_at` already rejects out-of-map points.
- Impact: invalid or stale client coordinates can reveal/hide an actual edge room
  instead of being rejected. Normal editor taps do have client bounds checks;
  the defect is in server validation, not an unauthenticated reveal endpoint.
- Reproduce: POST reveal/hide at x=-1 and beyond width/height on a small bounded
  disposable map; inspect operation history and fog pixels.
- Fix: validate `0 <= x < width` and `0 <= y < height` before interpretation/write,
  leaving in-map wall snapping unchanged unless separately agreed.
- Regression: all four boundaries and exact width/height reject without writes,
  version bumps or notifications; valid interior/wall-adjacent behavior remains.

## 29. Async image upload holds a SQLite write lock across await

- [ ] Open; static concurrency finding; live timing reproduction pending.
- Evidence: `web/admin/double_reveal.py`, `upload_image`, executes BEGIN IMMEDIATE
  and then awaits `asyncio.to_thread(images.store_map_image, ...)` inside that write
  transaction. Other async mutation routes perform blocking SQLite calls on the
  same event loop. `db.py` sets SQLite busy timeout to 15 seconds.
- Impact: while image processing is in the worker, a competing same-loop write can
  block the loop waiting for its lock. The upload coroutine then cannot resume to
  commit/release the lock until the competing write times out. This causes an
  avoidable stall/failed request, not necessarily a permanent deadlock. The second
  portal's separate event loop does not eliminate same-admin-loop contention.
- Reproduce: delay the image worker after upload obtains its write lock; send a
  second admin mutation needing a write; measure latency/errors and loop responsiveness.
- Fix: stage/validate the owned image before the transaction, then acquire the lock,
  reauthorize and revalidate stamp/dimensions before atomic install; clean up on all
  failed rechecks. Alternatively move the complete transaction to a coherent worker
  design. Do not simply remove the atomic compatibility check.
- Regression: overlapping upload/mutation remains responsive without lock-timeout
  failures; concurrent deletion/replacement/alternate changes still fail safely and
  leave no newly created orphan image. Use real SQLite and live requests.
